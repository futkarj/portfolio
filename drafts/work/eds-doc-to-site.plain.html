EDS Demo: From Google Doc to a 100-Lighthouse Site

TL;DR: I built a live Edge Delivery Services page where a rate table comes straight from a spreadsheet marketing edits. It scores 100 on Lighthouse performance on mobile. Try it below, then read how I'd demo it to a buyer.

Why this demo: after the EDS Adobe Learning and AEM Rockstar Masterclass (NYC, 2026), I wanted a demo that shows how EDS fits the content-velocity and performance problems I saw in eight years of AEM field engineering.

The buyer problem

  • "Publishing a page change takes a ticket and three days."
  • "Our Core Web Vitals hurt SEO and conversion."
  • "Every AEM project needs a big dev team."

What EDS changes (the 30-second pitch)

Content is authored in familiar tools (Google Docs/Sheets, SharePoint, or Document Authoring). Code is plain JS/CSS in GitHub. aem.live publishes to a CDN-first architecture built for a perfect Lighthouse score.

What I built

  • ✅ A site from Adobe's aem-boilerplate template, synced from GitHub with the AEM Code Sync app
  • ✅ Content authored in Document Authoring (da.live)
  • ✅ A custom Rate Table block (blocks/rate-table). Authors drop it on a page and link a spreadsheet. The sheet's columns become the table, one row can be highlighted, and on phones it turns into stacked cards. If the sheet can't load, it shows a polite fallback message instead of a broken page.
  • ✅ A rates sheet published as /rates.json, and a savings page that uses the block
  • 🚧 Next: a branded header and home page, and product cards

Results

Lighthouse on the live page, October 28, 2026:

SEO scored 69 only because aem.live tells search engines not to index branch URLs (x-robots-tag: noindex). That's intentional, and a production domain removes it.

Demo flow (7 minutes)

  1. Hook (1 min): run PageSpeed Insights live and show a score of 100.
  2. Author (2 min): change an APY in the rates sheet in da.live, click Preview, then Publish. The page updates in seconds, with no developer and no deploy.
  3. Structured content (2 min): open /rates.json to show the same sheet served as an API that other channels can use too.
  4. Developer view (2 min): the block is just blocks/rate-table/rate-table.js + .css. Push to GitHub, and the change is live on the branch URL.

Discovery questions this demo answers

  • How many people are involved in publishing a change today?
  • What's your current LCP / mobile Lighthouse score?
  • Where does marketing write content before it goes into the CMS?

Objections & answers

  • "Docs aren't a real CMS." → Show the Sidekick, preview/publish, and Universal Editor as the WYSIWYG option.
  • "What about our existing AEM Sites?" → EDS can run alongside AEM Sites; migrate page by page.

What's next
